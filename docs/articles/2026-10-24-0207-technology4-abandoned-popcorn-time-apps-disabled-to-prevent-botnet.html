Researchers Hijack Dead Piracy App's Servers, Use Powers Only to Tell It to Stop

Eye Security took over abandoned domains used by a Popcorn Time fork's updater and pushed an update that switched the updater off, sending more than 2 million downloads before handing the domains to a nonprofit.

The wire said: Abandoned Popcorn Time apps had to be disabled to prevent a zombie army · The Verge

By The Daily Spin Desk · TechnologyOct 24, 2026 02:07 UTC · 2 min read

Catch up

Popcorn Time was a 2010s app that made streaming pirated torrents as easy as using a legit service. Development of the fork Time4Popcorn was abandoned years ago, but its updater kept running on devices worldwide.

Why it matters

Old software you forgot about can keep running with full privileges and trust whoever controls a lapsed web address. Anyone who installed a piracy app a decade ago may still be carrying that risk.

Security firm Eye Security found that the updater for Time4Popcorn, a Popcorn Time fork, is still running on a large number of Windows, macOS and Android devices around the world, The Verge reported. The app's development ended years ago, but its updater kept phoning home to web domains that were no longer maintained. It did so over unencrypted HTTP, while running an outdated and insecure version of Chrome. The software is, in effect, a loyal employee still reporting to an office that closed.

The danger was straightforward. According to Eye Security's Niels Teusink, the updater could have been used to install and run essentially any software with full privileges. An attacker needed only to take over one of the abandoned domains, or use a man-in-the-middle attack (Translation: sit between your computer and the internet and quietly rewrite the conversation) to target particular machines. Surveillance was also possible, simply by identifying which machines were running the software. The Verge noted the result could have been a botnet, a network of hijacked computers that obeys one operator.

The researchers' solution was to register one of the domains themselves and send out an update instructing the updater to disable itself. They acknowledged ethical concerns about pushing code onto strangers' computers without being asked. Their defense was that the alternative "was to do nothing," and that the update process wasn't doing anything functional anyway and was only creating risk for users. It is an unusual position in security: the people with the keys to millions of machines used them to turn off one service.

The fix was deliberately modest. On Windows, Eye Security said the update stops and disables the service through the Service Control Manager, without deleting files. On macOS, a shell script runs a command that blocks the update process from starting. Android was left alone, because installing the update there would require actual user interaction first, and an update that asks permission is an update that gets ignored.

There was a hiccup. After the update was uploaded to VirusTotal, security programs flagged it as malware and blocked it, which left the vulnerable updater running. The researchers had to tweak the update. Software designed to protect computers from unauthorized remote code had, reasonably, treated unauthorized remote code as a problem, even when it was the helpful kind.

It remains unclear how many devices were at risk. Eye Security says it sent out over 2 million update downloads by March, when it stopped and transferred the domains to the Shadowserver Foundation, a web security nonprofit. The domains are now in the hands of people whose job is to not do anything interesting with them.

The broader lesson is that abandoned software does not retire. It sits on a hard drive, trusts an address nobody owns, and waits for whoever registers it first. This time that was a security firm. Next time, the sources suggest, it might not be.
