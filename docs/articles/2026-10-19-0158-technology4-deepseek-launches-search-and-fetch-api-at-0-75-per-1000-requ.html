DeepSeek Begins Charging AI Agents for Google, Which Was Free for Humans

The Chinese AI lab now sells search and page-fetching APIs at $0.75 per 1,000 successful requests, billed only when something actually works.

The wire said: DeepSeek search and fetch – $0.75 per 1000 successful requests · Hacker News

By The Daily Spin Desk · TechnologyOct 19, 2026 01:58 UTC · 3 min read

Catch up

DeepSeek, the Chinese AI lab known for its low-priced language models, has published documentation for two new tools: a Search API and a Fetch API. They let software agents look things up on the live web instead of relying on what the model memorized in training.

Why it matters

Models that can only recall old information are increasingly paired with tools that read the current web, and the price of that lookup becomes a line item for any business building on AI. Per-request billing that skips failures makes costs easier to predict than token-based pricing.

DeepSeek has added two web tools to its developer platform, according to the company's documentation, which was shared on Hacker News under the headline "$0.75 per 1000 successful requests." The Search API finds pages for a query and returns structured results from what the company calls its in-house search engine. The Fetch API takes a single URL and returns the page as Markdown. Put simply, DeepSeek is now selling the act of looking something up, which people have done for free for about thirty years.

Both tools are plain JSON endpoints that use the same bearer authentication as DeepSeek's existing API. Translation: if you already have a key for the model, the same key opens the door to the web. Search accepts queries of 1 to 128 characters and returns between 1 and 50 results, defaulting to 10. A developer can ask for full page content or leave it out, in which case the content field comes back as an empty string, a rare example of software being honest about having nothing to say.

The search syntax will be familiar to anyone who has ever tried to find an old forum post. The documentation lists operators for restricting or excluding sites, matching exact phrases, filtering by language, and setting date ranges with after: and before:. Translation: the same tricks power users learned to defeat bad search results are now offered to machines, which will use them without complaint or sighing.

Each result carries a relevance score from 0 to 3, with 1.5 or higher considered high quality, plus an authority rating from 0 to 4 where 3 or above marks highly authoritative sources. Results also include a short snippet meant for a screen and a longer summary, typically 600 to 800 characters, meant for a model. In other words, there is one version for humans and one for the agent doing the reading, and only one of them is expected to finish the paragraph.

The pricing is the headline. The headline figure is $0.75 per 1,000 successful requests, and the documentation says Search and Fetch are billed per successful request rather than by tokens or by the number of results returned. The documentation excerpt we received cuts off in the billing table, so we cannot say what each tool costs individually or whether there are different rates for search and fetch. At the quoted price, a thousand lookups costs less than a sandwich in most cities, though agents are not known for stopping at a thousand.

The error section is where the operational reality sits. The documentation lists a 402 for insufficient balance, a 429 for exceeding rate limits, and a 404 when a page cannot be retrieved because of site policy or an unsupported content type. It tells developers to retry on 408, 429 and 5xx errors, to top up the account on a 402, and not to retry other 4xx errors without changing the request. That is sound advice for software and, arguably, for most things.

Fetching, the documentation notes, is subject to the target site's availability and access policies. Translation: your agent can ask for any page, but the page is free to say no. How publishers feel about a growing number of automated readers is not covered in the material provided, so we will leave that argument to those who have invoices to send.

The strategic logic is straightforward. A model that can search is more useful than one that cannot, and a search tool that bills only on success gives customers one fewer reason to complain. Whether the per-request price proves cheaper than rival offerings is not something the source establishes. What it does establish is that the web is now being resold to the machines that read it, one successful request at a time.
