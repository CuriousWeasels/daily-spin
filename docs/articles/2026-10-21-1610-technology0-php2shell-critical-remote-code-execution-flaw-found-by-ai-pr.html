Two Flaws Found by AI in PHP Send Governments Offline to Stay Safe

Agencies from Finland to Japan told sites that cannot patch PHP to switch off, a fix for a bug the internet had carried for over a decade.

The wire said: Websites taken down worldwide as critical cyber-security update issued · BBC Technology

By The Daily Spin Desk · TechnologyOct 21, 2026 16:10 UTC · 2 min read

Catch up

PHP is a programming language that runs a large share of websites, including WordPress, Drupal and MediaWiki. Researchers at Wiz and Calif, using OpenAI models, found two critical flaws, and PHP released a patch on Wednesday.

Why it matters

Any site running PHP, including ones whose owners never chose it, could be taken over or leak passwords until patched. Some public services went dark so they would not be hacked.

According to the BBC, international governments and cyber-security agencies urged websites to fix two critical flaws in PHP, and told those unable to do so quickly to consider taking their sites offline. Finland temporarily shut its government's public web services, and the Netherlands' cyber-security agency took its own website down. This is one way to secure a website: remove the website.

The flaws carry severity ratings of 9.2 out of 10, according to Ars Technica, and are tracked as CVE-2026-109618 and CVE-2026-109619. Translation: CVE is a catalogue number for a known security flaw, so that everyone can panic about the same one. Wiz says the bugs involve how PHP handles fatal errors, especially running out of memory, which can leave corrupted state behind for a later request to reuse.

The consequence, per Wiz, is that attackers could read memory containing passwords, tokens and API keys, or run their own code on a server without logging in. Translation: unauthenticated remote code execution means a stranger can give your server orders without knowing any password. Wiz says this works even against a basic Hello World page, because the weakness is in PHP itself and not in the site built on top of it.

The discovery is the part the security industry is calling a turning point. Wiz said the flaws had gone undetected for more than a decade, and that frontier AI models made it practical to build working exploits across multiple applications in hours. Wiz argues that when expertise and time stop being barriers, complexity no longer protects anything. Translation: for years a bug was safe because it was too tedious to exploit, and a machine does not get bored.

The scale is why governments are involved. Wiz estimates roughly 70 percent of the internet is affected, though the BBC said it could not verify that figure. Security firm Huntress noted PHP quietly powers WordPress, Drupal, Joomla and Magento sites, and plenty of software that never mentions it. Sophos's Don Smith told the BBC the hard part is not installing the patch but finding every place PHP is running.

The effects were visible. Wikimedia took some systems down as a precaution, and some people could not reach parts of Wikipedia. Edinburgh council's website and BBC pages for Doctor Who and The Traitors became inaccessible, though the BBC noted none had confirmed a PHP link. DeviantArt said only that it was down for maintenance. The White House said federal agencies were working with leading AI labs to speed up a fix, and Japan's Prime Minister Sanae Takaichi urged people to check whether their public sites ran PHP.

Attackers are not waiting. Cloudflare's chief technology officer Dane Knecht said he was seeing early attacks emerging. Ars Technica reported that a purported exploit tool called PHP2Shell had been shown running code on several popular platforms, though that report was unconfirmed, and security firm watchTowr said it had confirmed the vulnerabilities are real.

The patch carries a catch. According to the BBC, the PHP Foundation issued the update only for the latest versions, and people on PHP 8.1 or older are urged to upgrade. CERT-EU said the flaws could affect every version back to PHP 5, released in 2004. Many organisations will now discover how long ago they stopped updating, and in some cases the last honest option is to unplug the server and wait.
