Sixteen-Year-Old Bug Discovered in Code That Starts Nearly Every Server

A 9.5-severity flaw in open source UEFI firmware code affects most server vendors, and the patch was published before the coordinated disclosure it was supposed to follow.

The wire said: Code-execution flaw in UEFI firmware affects most servers on planet Earth · Ars Technica

By The Daily Spin Desk · TechnologyOct 28, 2026 17:28 UTC · 3 min read

Catch up

UEFI is the firmware that runs when a computer powers on, before the operating system loads, and much of it is built from an open source codebase called TianoCore EDK II. Researchers found a memory-corruption flaw in it and planned to disclose it quietly in January.

Why it matters

Firmware bugs sit below the defenses that most security tools rely on, and fixing them means updating hardware across thousands of vendors and data centers. Most home users are unaffected, but organizations that boot machines over a network have a patching project ahead.

Ars Technica reported that a code-execution flaw in EDK II, the open source codebase used to build the boot-time firmware for most of the world's servers, has been made public ahead of schedule. The bug, tracked as CVE-2026-97631, is rated 9.5 out of 10 for severity. Virtually all major UEFI suppliers, including AMI, Insyde and Phoenix, use the reference code extensively, as did Microsoft's hardened fork, Project Mu.

Translation: UEFI is the first program a computer runs when you press the power button, and it is supposed to check that everything after it is trustworthy. A flaw there means an attacker gets to speak before the security guard has arrived for work.

The mechanism is a buffer overflow in the PXE Base Code driver, which lets machines boot from code downloaded over a local network. During that process the driver listens for ICMP error messages (translation: the network's way of saying something went wrong) and copies each into a fixed 504-byte field. According to the official advisory, a longer message still gets copied, and the destination pointer advances by the cumulative length rather than the per-fragment length. So an oversized message writes attacker-controlled bytes past the end of the field. Ars reports the flaw is 16 years old, which is roughly how long it sat in the code while everyone assumed someone else had checked.

The disclosure did not go as planned. The discoverers, Alex Matrosov of Anthropic and Dan Holmes of Google, had arranged for coordinated disclosure in January. Then AMI published a pull request last month that described the vulnerability and included the fix. Once the discoverers noticed, TianoCore members issued a public advisory last week. Translation: the instructions for the lock were posted before the locksmiths were done. Ars notes this came six days after another botched disclosure involving a critical PHP flaw.

The caveats are real. An attacker needs some level of access to the local network, which points to malicious insiders or intruders such as nation-states and ransomware operators who are already inside and want more privilege. Jesse Michael of Eclypsium told Ars that exploits must be tuned to each target model, version and configuration because memory addresses differ. Ars also reports no evidence yet that the flaw offers an initial way into a network.

Still, HD Moore of Dragos said the bug could let an attacker hijack program flow while the boot process still has access to sensitive components like the TPM, potentially breaking disk encryption, and more easily if a device is stolen. The code runs in ring 0, the CPU's most privileged level, and the payload does not persist on its own, though it can open the door to others that do.

There is one piece of good news. Michael said that, unlike earlier Secure Boot problems such as BootHole, this one can be fixed with a basic code change delivered through a BIOS or UEFI update, without key revocations or updates to operating system and provisioning media. Home and small office users who boot only from disk drives are not affected.

The bad news is the supply chain. Updates must pass from EDK II to firmware vendors to hardware makers to the administrators of millions of devices. Moore said the flaw is likely to become a forever bug on systems that are no longer supported. Previous entries in this genre include LogoFail, PixieFail and PKFail, so the category is not short of members.

What to watch: how quickly vendors ship updated firmware, and whether working exploits appear now that the fix is public.
